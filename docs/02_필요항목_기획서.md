# 일정관리 시스템 — 필요 항목 정리

> 프로젝트: 02. 일정관리자
> 작성 기준일: 2026-07-15
> 목적: 일정관리 시스템 구축에 필요한 데이터 항목(필드), 분류 체계, 핵심 기능, 화면 구성을 한 번에 정리한 기획 기준 문서

이 문서는 **팀 협업 + 데이터 항목 중심**을 기본 전제로 작성했습니다. 개인용으로 쓸 경우 담당자·참석자·공유 관련 항목을 생략하면 되고, 프로젝트 관리 중심으로 확장할 경우 마감일·진행률·프로젝트 연결 항목을 핵심으로 두면 됩니다.

---

## 1. 핵심 데이터 항목 (일정 엔티티)

일정 하나가 가지는 정보입니다. "필요한 항목"의 중심이 되는 부분으로, 이 표가 곧 데이터 구조(스키마)의 기준이 됩니다.

| 그룹 | 항목명 | 필드 키 | 타입 | 필수 | 설명 |
|---|---|---|---|---|---|
| 기본 | 일정 ID | `id` | 고유값(UUID) | ● | 시스템이 자동 부여하는 식별자 |
| 기본 | 제목 | `title` | 텍스트 | ● | 일정명. 목록·캘린더에 표시되는 대표 이름 |
| 기본 | 상세 설명 | `description` | 긴 텍스트 | ○ | 안건, 준비물, 참고 내용 등 |
| 분류 | 일정 유형 | `type` | 선택 | ● | 업무/회의/개인/마감 등 (3장 참고) |
| 분류 | 카테고리·프로젝트 | `project_id` | 참조 | ○ | 상위 프로젝트나 카테고리 연결 |
| 분류 | 태그·라벨 | `tags` | 다중선택 | ○ | 자유 라벨 (예: 긴급, 외부, 검토필요) |
| 일시 | 시작 일시 | `start_at` | 날짜+시간 | ● | 일정 시작 시각 |
| 일시 | 종료 일시 | `end_at` | 날짜+시간 | ● | 일정 종료 시각 |
| 일시 | 종일 여부 | `is_all_day` | 참/거짓 | ○ | 시간 없이 하루 단위로 처리 |
| 일시 | 마감일 | `due_date` | 날짜 | ○ | 태스크형 일정의 데드라인 |
| 일시 | 반복 설정 | `recurrence` | 규칙 | ○ | 반복 주기·요일·종료 조건 (4장 참고) |
| 상태 | 상태 | `status` | 선택 | ● | 예정/진행중/완료/보류/취소 (3장 참고) |
| 상태 | 우선순위 | `priority` | 선택 | ○ | 높음/중간/낮음 (3장 참고) |
| 상태 | 진행률 | `progress` | 숫자(0~100%) | ○ | 태스크 진행 정도 |
| 사람 | 담당자 | `owner` | 참조(사용자) | ○ | 이 일정의 책임자 |
| 사람 | 참석자·공유 대상 | `participants` | 다중참조 | ○ | 함께 보는/참여하는 사람 |
| 장소 | 장소·링크 | `location` | 텍스트/URL | ○ | 오프라인 위치 또는 온라인 회의 링크 |
| 알림 | 알림·리마인더 | `reminders` | 다중값 | ○ | 시작 10분 전, 1일 전 등 |
| 부가 | 첨부파일 | `attachments` | 파일 | ○ | 문서·이미지 등 |
| 부가 | 색상 | `color` | 선택 | ○ | 캘린더 표시 색상 (유형/우선순위 연동 가능) |
| 부가 | 메모·코멘트 | `notes` | 긴 텍스트 | ○ | 후속 기록, 협업 코멘트 |
| 시스템 | 생성자 | `created_by` | 참조 | ● | 자동 기록 |
| 시스템 | 생성일시 | `created_at` | 날짜+시간 | ● | 자동 기록 |
| 시스템 | 수정일시 | `updated_at` | 날짜+시간 | ● | 자동 기록 |

**최소 구성(MVP)으로 좁힌다면:** 제목 · 시작/종료 일시 · 유형 · 상태 · 담당자 · 메모 — 이 6개만으로도 동작하는 일정관리가 됩니다. 나머지는 필요에 따라 단계적으로 추가하면 됩니다.

## 2. 사용자·권한 항목 (팀 협업 시)

여러 사람이 함께 쓰는 경우 필요한 항목입니다. 개인용이면 이 장은 건너뛰어도 됩니다.

| 항목명 | 필드 키 | 설명 |
|---|---|---|
| 사용자 ID | `user_id` | 사용자 식별자 |
| 이름 | `name` | 표시 이름 |
| 이메일 | `email` | 로그인·알림 발송용 |
| 소속·부서 | `team` | 부서/팀 구분 |
| 역할·권한 | `role` | 관리자 / 편집자 / 뷰어 |
| 프로필 색상·이미지 | `avatar` | 참석자 표시용 |

권한은 최소 세 단계면 충분합니다: **관리자**(전체 관리), **편집자**(일정 등록·수정), **뷰어**(조회만).

---

## 3. 분류 체계 (선택값 정의)

드롭다운으로 쓰이는 값들을 미리 정해두면 데이터가 일관되게 쌓입니다.

**일정 유형(`type`)**
업무 태스크 · 회의/미팅 · 외부 약속 · 개인 일정 · 마감/데드라인 · 휴가/부재 · 기타

**상태(`status`)**
예정(To Do) · 진행중(In Progress) · 완료(Done) · 보류(On Hold) · 취소(Canceled)

**우선순위(`priority`)**
높음(긴급·중요) · 중간(기본값) · 낮음

각 값에는 색상을 매핑해 두는 것을 권장합니다. 예: 진행중=파랑, 완료=초록, 보류=회색, 취소=옅은 빨강 / 우선순위 높음=빨강.

---

## 4. 반복 일정 규칙 항목

정기 회의·주간 업무처럼 반복되는 일정을 위한 항목입니다.

| 항목명 | 설명 | 예시 |
|---|---|---|
| 반복 주기 | 매일 / 매주 / 매월 / 매년 | 매주 |
| 반복 요일·일자 | 주기 내 반복 시점 | 월·수·금 |
| 반복 간격 | N주마다, N개월마다 | 2주마다 |
| 종료 조건 | 종료일 지정 / N회 반복 / 무기한 | 2026-12-31까지 |
| 예외 처리 | 특정 회차 건너뛰기·수정 | 공휴일 제외 |

## 5. 주요 기능

시스템이 제공해야 할 기능을 우선순위 순으로 정리했습니다.

**필수 기능**
일정 등록·조회·수정·삭제, 캘린더 뷰(월/주/일), 목록(리스트) 뷰, 상태·우선순위·유형별 필터, 키워드 검색.

**권장 기능**
알림·리마인더, 반복 일정, 담당자·참석자 지정 및 공유, 태그·프로젝트별 그룹핑, 오늘/이번 주 요약 대시보드.

**확장 기능**
드래그로 일정 이동·기간 조정, 외부 캘린더(구글/아웃룩) 연동, 파일 첨부, 코멘트·활동 로그, 통계(완료율·부서별 부하), 모바일 대응.

## 6. 화면 구성

| 화면 | 핵심 내용 |
|---|---|
| 대시보드(홈) | 오늘·이번 주 일정 요약, 마감 임박, 내 담당 일정, 상태별 건수 |
| 캘린더 | 월/주/일 전환, 일정 블록 표시, 클릭 시 상세, 드래그 이동 |
| 목록(리스트) | 표 형태 정렬·필터, 상태/우선순위 뱃지, 일괄 관리 |
| 일정 등록·상세 | 1장의 항목을 입력·수정하는 폼, 반복·알림·참석자 설정 |
| 검색·필터 | 유형·상태·기간·담당자·태그 조합 검색 |
| 설정 | 분류값 관리, 알림 기본값, 사용자·권한, 색상 규칙 |

## 7. 다음 단계 제안

이 정리를 바탕으로 이어서 만들 수 있는 것들입니다. 원하시는 방향을 알려주시면 바로 진행하겠습니다.

1. **데이터 항목 정의(스키마) 스프레드시트** — 위 1~4장을 개발·DB에 바로 쓰도록 엑셀 표로 정리
2. **화면 프로토타입(HTML)** — 캘린더/목록/등록 화면을 실제 동작하는 시안으로 제작
3. **와이어프레임·IA 문서** — 화면 흐름과 정보 구조 중심의 설계 문서
4. **범위 확정** — 개인용 / 팀 협업 / 프로젝트 관리 중 목표를 좁혀 항목을 재정리
